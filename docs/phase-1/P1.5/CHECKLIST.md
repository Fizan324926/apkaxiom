## B. ZIP local file header (LFH) — formalization

Layout per APPNOTE.TXT 6.3.10 §4.3.7. Source: [`theorems/Apkaxiom/Zip/LocalHeader.lean`](../../../theorems/Apkaxiom/Zip/LocalHeader.lean).

### B-1. Wire format

| offset | size | field | Lean type | Rust type |
|---:|---:|---|---|---|
| 0 | 4 | signature `0x04034b50` | `UInt32` constant | `u32` constant |
| 4 | 2 | version needed | `UInt16` | `u16` |
| 6 | 2 | general flags | `UInt16` | `u16` |
| 8 | 2 | compression method | `UInt16` | `u16` |
| 10 | 2 | last-mod time | `UInt16` | `u16` |
| 12 | 2 | last-mod date | `UInt16` | `u16` |
| 14 | 4 | CRC-32 | `UInt32` | `u32` |
| 18 | 4 | compressed size | `UInt32` | `u32` |
| 22 | 4 | uncompressed size | `UInt32` | `u32` |
| 26 | 2 | filename length (n) | `UInt16` | `u16` |
| 28 | 2 | extra-field length (m) | `UInt16` | `u16` |
| 30 | n | filename bytes | `ByteArray` | `Vec<u8>` |
| 30+n | m | extra-field bytes | `ByteArray` | `Vec<u8>` |

Total bytes consumed by a successful parse: `30 + n + m`.

### B-2. Error variants (cross-language tag enumeration)

| Lean / Rust variant | tag byte | Meaning |
|---|---:|---|
| `ShortHeader` | 1 | Input shorter than the 30-byte fixed prefix |
| `BadSignature` | 2 | Magic ≠ `0x04034b50` |
| `ShortName` | 3 | Filename region runs past EOF |
| `ShortExtra` | 4 | Extra-field region runs past EOF |

Lean theorem `ParseError.tag_injective : Function.Injective tag` ensures
the four tags are pairwise distinct; the differential harness diffs
the integers across languages.

## C. ZIP end of central directory (EOCD) — formalization

Layout per APPNOTE.TXT 6.3.10 §4.3.16. Source: [`theorems/Apkaxiom/Zip/Eocd.lean`](../../../theorems/Apkaxiom/Zip/Eocd.lean).

### C-1. Wire format

| offset | size | field | Lean type | Rust type |
|---:|---:|---|---|---|
| 0 | 4 | signature `0x06054b50` | `UInt32` constant | `u32` constant |
| 4 | 2 | this-disk number | `UInt16` | `u16` |
| 6 | 2 | CD-start disk number | `UInt16` | `u16` |
| 8 | 2 | entries on this disk | `UInt16` | `u16` |
| 10 | 2 | total entries | `UInt16` | `u16` |
| 12 | 4 | CD size | `UInt32` | `u32` |
| 16 | 4 | CD offset | `UInt32` | `u32` |
| 20 | 2 | comment length (k) | `UInt16` | `u16` |
| 22 | k | comment | `ByteArray` | `Vec<u8>` |

### C-2. Error variants

| Lean / Rust variant | tag byte | Meaning |
|---|---:|---|
| `ShortFixed` | 1 | Input shorter than the 22-byte fixed prefix |
| `BadSignature` | 2 | Magic ≠ `0x06054b50` |
| `ShortComment` | 3 | Comment region runs past EOF |
| `InconsistentDisks` | 4 | `disk_number ≠ cd_start_disk` (multi-volume archives — out of scope; see §G-2 / ADR-0017) |

### C-3. Suffix locator

`findEocd` (Lean) and `find_eocd` (Rust) scan backwards from EOF for
the signature, with the search window capped at
`fixed_size + max_comment_len = 22 + 65535 = 65557` bytes. Mirrored
byte-for-byte across languages.

## E. Corpus generator — `tools/zip-corpus-gen`

Source: [`tools/zip-corpus-gen/src/main.rs`](../../../tools/zip-corpus-gen/src/main.rs).
Output: [`corpus/zip/`](../../../corpus/zip/).

### E-1. Sample distribution

| Subdir | Count | Composition |
|---|---:|---|
| `corpus/zip/lfh-valid/` | 1000 | Random valid LFHs with name length ∈ [0, 32), extra length ∈ [0, 16) |
| `corpus/zip/lfh-adversarial/` | 500 | Equal slices: 125 truncated (`ShortHeader`) / 125 bad-magic (`BadSignature`) / 125 short-name (`ShortName`) / 125 short-extra (`ShortExtra`) |
| `corpus/zip/eocd-valid/` | 100 | Random valid EOCDs, comment ∈ [0, 64) |
| `corpus/zip/eocd-adversarial/` | 200 | 50/50/50/50 across the 4 EOCD error variants |
| **total** | **1800** | |

Each subdir carries a `manifest.json` recording the expected parse
verdict per sample. The generator's RNG is a tiny LCG seeded with the
AXIOM-IR capnp file ID (`0xa9c1d4b1f7e23d51`); rerunning the
generator produces a byte-identical corpus.

### E-2. Determinism gate

The `p15-corpus-drift` CI job re-runs `make p15-corpus` and asserts
`git diff --exit-code corpus/zip/`. Drift means either the generator
changed shape, the LCG seed shifted, or the wire format itself
moved — any of which is a v0.1 contract change requiring an ADR
amendment.

## F. Differential harness — `tools/zip-differential`

Source: [`tools/zip-differential/src/main.rs`](../../../tools/zip-differential/src/main.rs).

### F-1. Algorithm

For every sample under `corpus/zip/`:

1. Run `axiom_zip_ref::lfh::parse_lfh` / `eocd::parse_eocd` on the
   bytes; produce a `Verdict` (either `Ok { consumed }` or
   `Err { tag }`).
2. Append the sample's bytes to a *batched Lean driver*. Every 50
   samples, write the driver to a tmp file, invoke `lake env lean
   --run`, and read one verdict line per sample from stdout.
3. Compare verdicts pairwise. Any mismatch flunks the gate.

Batching keeps each Lean elaboration under ~150 KB (the elaborator
OOMs on larger driver files); 50 samples × 36 batches × ~4 s/batch
= ~2-3 minutes for the full 1,800 samples.

### F-2. Result on the committed corpus

Last verified on `linux-x86_64`:

```
  eocd-adversarial: 200/200 agree
  eocd-valid: 100/100 agree
  lfh-adversarial: 500/500 agree
  lfh-valid: 1000/1000 agree

TOTAL: 1800/1800 agree (all_pass=true)
```

The structural agreement count (`all_pass: true`) is deterministic
across runs; the `differential-summary.json` file recording it is
gitignored because it carries per-host JSON timestamps. The CI gate
asserts `all_pass = true` without committing the summary file.

## G. ADRs (folded inline)

### G-1. ADR-0016 — libziparchive vendoring posture

**Status:** Accepted (P1.5, 2026-05-04). **Owner:** G1.

**Decision.** P1.5 ships **two prongs of the differential gate** (Lean
↔ Rust on 1,800 corpus samples). The third prong — Lean ↔ AOSP
`libziparchive` — is **deferred to P1.13 / P1.18**. We do **not**
sync the AOSP source tree in P1.5.

**Why.** The AOSP repo sync is 5-8 GB on disk, requires a network
of build prerequisites (`flex bison build-essential libstdc++…`)
that fight our Nix-pinned toolchain, and demands ongoing version
pinning across Android API levels. The added confidence from a
third prong on Phase-1 inputs is marginal: the LFH and EOCD wire
formats are stable across every Android version Phase-1 cares
about (L through V). The 1,800-sample Lean ↔ Rust gate already
binds the soundness contract.

**When the third prong joins.** P1.13 (continuous fuzzing) needs an
adversarial corpus regenerator that talks to libziparchive anyway;
P1.18 (production benchmarks) needs the AOSP build for differential
performance. Vendoring lands then.

**Trade-offs.** If a Phase-2 forensic pass uncovers an
LFH-or-EOCD-class corner case where libziparchive's behaviour
matters and our spec disagrees, we eat a P1.5 retro. The corpus
size (1,800 vs. 1,000 spec target) and the diversity (4 error
variants × structured-mutation seed pool) buy headroom against
this.

### G-2. ADR-0017 — ZIP64 multi-volume support out of v0.1 scope

**Status:** Accepted (P1.5, 2026-05-04). **Owner:** G1.

**Decision.** v0.1 of the ZIP layer rejects any archive with
`disk_number ≠ cd_start_disk` via the `InconsistentDisks` /
`inconsistentDisks` parse error. ZIP64 multi-volume archives are
out of scope for Phase 1.

**Why.** APKs are single-volume in 100% of the F-Droid corpus and
in 100% of malware corpora we have surveyed. The ZIP64 multi-volume
extension exists in APPNOTE.TXT but no Android packaging tool
produces it. Supporting it now would inflate the parser surface
without delivering a concrete win.

**When this re-opens.** Phase 2 (forensics) revisits if we surface
a real-world APK that fails to parse for this reason. The error
variant `InconsistentDisks` is intentionally distinguishable so
the upgrade path is clean.
