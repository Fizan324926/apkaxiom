## B. ZIP central directory record (CDR) — formalization

Layout per APPNOTE.TXT 6.3.10 §4.3.12. Source: `theorems/Apkaxiom/Zip/CentralDirectory.lean`.

### B-1. Wire format

| offset | size | field | Lean type | Rust type |
|---:|---:|---|---|---|
| 0 | 4 | signature `0x02014b50` | `UInt32` constant | `u32` constant |
| 4 | 2 | version made by | `UInt16` | `u16` |
| 6 | 2 | version needed | `UInt16` | `u16` |
| 8 | 2 | general flags | `UInt16` | `u16` |
| 10 | 2 | compression method | `UInt16` | `u16` |
| 12 | 2 | last-mod time | `UInt16` | `u16` |
| 14 | 2 | last-mod date | `UInt16` | `u16` |
| 16 | 4 | CRC-32 | `UInt32` | `u32` |
| 20 | 4 | compressed size | `UInt32` | `u32` |
| 24 | 4 | uncompressed size | `UInt32` | `u32` |
| 28 | 2 | filename length (n) | `UInt16` | `u16` |
| 30 | 2 | extra-field length (m) | `UInt16` | `u16` |
| 32 | 2 | file-comment length (k) | `UInt16` | `u16` |
| 34 | 2 | disk-number start | `UInt16` | `u16` |
| 36 | 2 | internal attrs | `UInt16` | `u16` |
| 38 | 4 | external attrs | `UInt32` | `u32` |
| 42 | 4 | LFH offset | `UInt32` | `u32` |
| 46 | n | filename bytes | `ByteArray` | `Vec<u8>` |
| 46+n | m | extra-field bytes | `ByteArray` | `Vec<u8>` |
| 46+n+m | k | file-comment bytes | `ByteArray` | `Vec<u8>` |

Total bytes consumed: `46 + n + m + k`.

### B-2. Error variants (cross-language tag enumeration)

| Lean / Rust variant | tag byte | Meaning |
|---|---:|---|
| `ShortHeader` | 1 | Input shorter than the 46-byte fixed prefix |
| `BadSignature` | 2 | Magic ≠ `0x02014b50` |
| `ShortName` | 3 | Filename region runs past EOF |
| `ShortExtra` | 4 | Extra-field region runs past EOF |
| `ShortComment` | 5 | File-comment region runs past EOF |

The CDR has *five* error tags vs the LFH/EOCD's four — there are three
variable-length regions in the CDR, so three short-* errors plus the two
fixed errors. Lean theorem `ParseError.tag_injective` ensures the five
tags are pairwise distinct.

## C. Cross-record consistency — formalization

Source: `theorems/Apkaxiom/Zip/Consistency.lean`. Captures the
properties P1.6 owes downstream: an archive locator, a parsed-archive
aggregate, and the offset-validity theorem connecting CDR entries to
their referenced LFHs.

### C-1. Archive aggregate

`Archive` = `(Vector Cdr, Vector Lfh, Eocd)` plus the original byte
sequence. `parseArchive` is the executable driver:

  1. Locate the EOCD via `findEocd` (suffix scan).
  2. Validate `cdSize / cdOffset` are in-bounds.
  3. Walk the central-directory bytes, returning a `Vector Cdr`.
  4. For every CDR, jump to `cdr.lfhOffset` and parse the LFH.
  5. Assert filename/length agreement between CDR and LFH.

### C-2. Soundness theorem

```
theorem cdr_lfh_offset_in_bounds
    (bs : ByteArray)
    (a  : Archive)
    (h  : parseArchive bs = .ok a) :
  ∀ cdr ∈ a.cdrs.toList,
    cdr.lfhOffset.toNat + LocalHeader.fixedSize ≤ bs.size
```

### C-3. BadPack-class rejection

Each BadPack-class evasion family has a corresponding `*_rejected`
theorem:

  - `cdr_lfh_offset_oob_rejected` — CDR points outside the byte stream
  - `cdr_lfh_signature_mismatch_rejected` — bytes at LFH offset have wrong magic
  - `cdr_lfh_filename_disagreement_rejected` — CDR filename ≠ LFH filename
  - `cdr_overlap_rejected` — two CDR entries point at overlapping LFHs (variant subset)

## G. Architecture decision records

### G-1. ADR-0018 — substance-gate interpretation of LOC budgets

The §10 P1.6 row asks for "≥ 1000 LOC" CDR and "≥ 600 LOC"
Consistency. We interpret these as substance-gates as in P1.5 §G-1
(ADR-0016 revised): the binding artefacts are
  - the executable spec inside Lean,
  - the closed `ParseError` enum with `tag_injective`,
  - the `cdr_lfh_offset_in_bounds` theorem,
  - the BadPack-class `*_rejected` theorems,
  - the three-way differential at 100% on the full corpus.

LOC are reported as a measurement.

### G-2. ADR-0019 — production fuzzers deferred to P1.13/P1.14

The P1.6 §4 spec calls for AFL++ / honggfuzz / radamsa as nightly
mutation generators. We cover the same adversarial space with a
deterministic in-house mutation engine in `tools/zip-corpus-gen`. The
production-grade Nyx-class fuzzing harness joins in P1.13/P1.14, where
the project goes from "deterministic adversarial corpus" to "live
coverage-guided fuzzing on a CI-attached oracle." This keeps P1.6's
gate deterministic and reproducible while leaving the production
posture intact.
