## 7. Features & Functions Delivered (Comprehensive)

### Lean theorem
```lean
theorem no_read_contacts (apk : APK) : ∀ (path : ExecutionPath apk),
  path.calls.all (fun call ⇒ call.permission ≠ Permission.READ_CONTACTS)
```

### Witness extractor
- Lift DEX (Phase-2 opcode subset) to AXIOM-IR-symbolic
- Per-component path enumeration (bounded, abstract-domain-aware)
- Static-analysis pass: identify all call-sites for `getContentResolver().query(ContactsContract...)` and equivalents
- AOSP-version-specific: identifies READ_CONTACTS-gated APIs across A8–A15

### Halo2 circuit
- Variables: per-component reachable-call multi-set (over-approximated)
- Constraint: for every variable, the call's permission ≠ READ_CONTACTS
- Custom gates: `permission_check`, `path_enumeration`
- Lookup tables: AOSP API → permission mapping (precomputed, hashed via Poseidon2)
- Circuit size: target ≤ 2^16 rows on typical APK (≤ 5 s prove on H100)

### Witness format
- Per-component: list of (callsite_id, callee_class, callee_method, permission_label)
- Cryptographically committed via Poseidon2

### Soundness chain
- Apply P4.4's `lean_implies_halo2_circuit` theorem with this specific Lean instance
- Result: a `NoReadContacts` `.axc` claim is cryptographically equivalent to the Lean theorem

### Demo on Bench-1K
- Run the full pipeline on 1000 APKs
- Per-APK: compile witness, prove, verify
- Measure prove + verify times
- Target: ≥ 95% of APKs prove successfully (others may have constraint-explosion → UNKNOWN)

### Documentation
- `docs/circuit-no-read-contacts.md` — circuit design, witness format, AOSP-API mapping
